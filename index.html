Projects

Financial-statement extraction service for A-share company reports2026

Project lead/Write-up

  • A service in production that extracts the balance sheet, income statement and cash-flow statement from A-share annual, half-year and quarterly reports into about 270 standard fields. Every value carries a confidence, and reports that fail the accounting checks go to human review.
  • One batch of 4,735 annual reports for 2025 ran in about 30 hours on a GPU cluster, 4,733 of them successfully; across the full batch, 99.90% of 1.29 million values agree with a commercial database.
  • The row-to-field mapping is learned from data, with no hand-written rules. On 1,200 held-out reports of non-financial companies: 99.85% precision at 98.06% coverage.
DataDig: real-time event tracking over financial news2025–2026

Clustering, story chains and retrieval in a team system/Write-up

  • Splits a stream of Chinese financial news into short facts and, every few minutes, groups them into ongoing events that timelines, summaries and alerts point to. In a three-day replay, 29,832 extracted facts became 7,628 after deduplication and 4,510 event clusters.
  • My part keeps event identities stable across re-clustering, which otherwise scatters about 1% of existing members: a two-stage repair against splits and merges, cluster IDs inherited by Jaccard overlap, and reuse of earlier embeddings above 0.9 cosine similarity.
  • Event chains record only what changed since the previous step, and retrieval looks up real documents first and writes the bridging query afterwards.
Agent Claim Network2026

Open-source team project; agent features and the evaluation/Write-up/Code

  • An open-source terminal coding agent that saves what it works out as “claims”, each with a scope, evidence and a confidence, for other agents to look up. I built the tool the agent uses to look claims up while solving and the /claim panel, OAuth login for MCP servers, and recovery when the model service refuses a request mid-session.
  • Built the evaluation on DeepSWE v1.1: 111 tasks, four isolated arms per task, a claim quality gate and paired statistics. The agent that fetches claims on demand passed 73 tasks against 63 for the baseline, with 15.9% fewer input tokens (single run, McNemar p ≈ 0.099).
